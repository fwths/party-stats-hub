# Audit Report Template

This document defines the standard structure for all audit reports generated by the audit system.

The purpose of this template is to:

- Ensure consistent reporting
- Enable comparison between audit runs
- Support trend analysis
- Improve executive review
- Simplify backlog generation
- Improve finding traceability

All agents should follow this structure unless their prompt explicitly requires additional sections.

---

# Report Metadata

## Report Information

```yaml
report_name:
report_type:
generated_by:
generated_on:
repository_version:
audit_cycle:
```

Example:

```yaml
report_name: D&D Domain Audit

report_type: Domain Review

generated_by: D&D Domain Agent

generated_on: 2026-06-29

repository_version: main

audit_cycle: 2026-Q2
```

# Executive Summary

Provide a concise summary of the audit.

The summary should answer:

- What was reviewed?
- What appears healthy?
- What appears risky?
- What should happen next?

Maximum length:

1–2 pages.

---

# Overall Assessment

Choose one:

```text
Healthy

Healthy With Improvements

Requires Remediation

High Risk
```

Provide justification.

---

# Health Score

Use a 1-10 scale.

```text
1-3   Critical Risk

4-5   Significant Concerns

6-7   Manageable Risk

8-9   Strong

10    Exceptional
```

Example:

```text
Rules Accuracy Score: 7/10
```

---

# Report Quality Rules

Every report must:

- Use finding IDs
- Use official severity levels
- Reference ownership
- Follow finding schema
- Separate facts from opinion
- Avoid duplicate findings
- Avoid speculative findings

---

# Report Completion Checklist

Before a report is considered complete:

```text
□ Executive Summary included

□ Scope defined

□ Findings summarized

□ Detailed findings included

□ Severity applied

□ Ownership validated

□ Regressions reviewed

□ Recommendations included

□ Final recommendation provided

□ Confidence assessment provided
```

A report that satisfies this checklist is considered audit-ready.
